# 0006. 脆弱性情報の取り込みは、置き場の鍵で同時に 1 つだけにする

- ステータス: 承認
- 日付: 2026-10-30

## 文脈

- `advisories sync` は cron で毎日流し、手でも流す。2 つが重なることはありうる
- NVD の一括ファイルは `KADOBAN_DATA_DIR/nvd/` の同じ名前に取る。続きから取るために `.part` に書き足すので、2 つが同時に書くと中身が混ざる。置き換えや削除もぶつかる(PR #3 のレビュー 2 周目)
- DB の書き込みは、書く取引を `BEGIN IMMEDIATE` で始めて守っている(PR #2)。ただし、取引をまたぐ「写しの新しさを読んでから記録する」の間は守れない
- 初回の取り込みは 1 時間半ほどかかる(ADR 0004)

## 検討した選択肢

1. `KADOBAN_DATA_DIR/sync.lock` を OS の鍵(flock)で押さえ、押さえられなければ始めない
2. DB に「取り込み中」の行を書き、終わったら消す
3. 何もしない。DB の取引だけで守る
4. NVD のファイルごとに鍵を掛ける

## 決定

PR #3 のレビューを受けて Claude が 1 を提案し、高橋さんが承認した。

- 取り込みの全体(KEV と NVD)を鍵の中で行う。ほかの取り込みが鍵を持っていれば、待たずに文を出して 1 で終わる
- DB の書き込みの守り(`BEGIN IMMEDIATE`)と、写しの新しさを前より古くしない記録は、そのまま残す

## 理由

- flock の鍵は、プロセスが落ちれば OS が外すので、残った鍵で止まり続けることが無い。2 は、落ちたときに行が残り、手で消すまで始められない
- 3 は、NVD のファイルの書き足しを守れない
- 4 は、ファイルを守れても、写しの新しさを読んでから記録するまでの間を守れない。取り込みの全体を 1 つに絞る方が単純
- 待たずに終えるのは、1 時間半の取り込みの後ろで cron が待ち続けないため。次の日の cron が拾う

## 受け入れたトレードオフ

- flock は macOS と Linux で使える。Windows とネットワークのファイルシステムでは効かない
- 長い取り込みの間、手で流した取り込みは始められない

## 再検討する条件

- Windows やネットワークのファイルシステムに置くことになったとき
- 取り込みを KEV と NVD で別々に流したくなったとき
