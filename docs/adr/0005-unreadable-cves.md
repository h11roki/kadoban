# 0005. NVD の形の読めない CVE は飛ばして印を残し、1 つのファイルで 20 件と 1% の多い方を超えたら止める

- ステータス: 承認
- 日付: 2026-10-30

## 文脈

- ADR 0004 で、NVD の CVE を pydantic で形を確かめてから写すことにした。必須の項目(`id`、`published`、`lastModified`、`vulnStatus`)が無いものや、CPE が 13 の欄に分けられないものは読めない
- 最初の作りは、読めない CVE が 1 件でもあると取り込み全体を止めた。止まると写しの新しさが進まず、同じ CVE が更新分のファイルに 8 日、年ごとのファイルにはずっと載るので、毎日同じところで止まり続ける(PR #3 のレビュー 1 周目)
- 飛ばすだけにすると、その CVE の古い範囲が手元に黙って残る。照合はそれを最新と思って使う(レビュー 2 周目)
- 更新分のファイルは静かな週には数百件しかない。1% だけを境にすると、数件の崩れで止まる(レビュー 2 周目)
- 元の JSON は全て残している(ADR 0004)。読み方を直せば、範囲は取り直さずに作り直せる
- 2024 年分の 224,268 と 2025 年分の 218,009 の CPE は、全て 13 の欄に分けられた

## 検討した選択肢

1. 1 件でも読めなければ止める
2. 読めない CVE は飛ばし、ID と理由を出すだけにする
3. 読めない CVE は飛ばして ID と理由を出し、印を表に残す。1 つのファイルで多すぎれば形が変わったとみなして止める
4. 3 に加え、ファイルの全体を 1 つの取引にし、多すぎれば書いた分も巻き戻す

## 決定

PR #3 のレビューを受けて Claude が 3 を提案し、高橋さんが承認した。

- 読めない CVE は `unreadable_cves` に ID、理由、見た日時を残す。手元に、それより新しいか同じ更新日時の版があれば印を付けない(古い年のファイルの崩れた版で、新しい版に印を付けない)
- 同じか新しい更新日時の読める版が書かれたら、印を消す。読み方を直して流し直せば消える
- 照合では、印のある CVE は手元の範囲が古いかもしれないので要確認にする
- 1 つのファイルで、読めない数が 20 件と読んだ数の 1% の多い方を超えたら止め、写しの新しさを進めない。印は止めるかどうかを決めてから書く

## 理由

- 1 は、1 件の崩れで写し全体が古くなり続ける。2 は、古い範囲が黙って残り、該当を非該当とする誤り(ADR 0002 で最も重い誤り)を生みうる
- 印を残せば、照合が「範囲が古いかもしれない」と分かり、ADR 0002 の「迷ったら要確認」に乗せられる
- 下限の 20 件は、数百件の更新分のファイルで数件の崩れに止まらないため。1% は、項目の名前が変わるような形の変化で大半が読めなくなるのを捉えるため
- 4 は、大きなファイルの間ずっと書き込みの鍵を持つ。読めた分は元の JSON から作り直せるので、巻き戻すほどの得が無い

## 受け入れたトレードオフ

- 形の変化で止めても、それまでに読めた分は書いたまま残る。読み方を直して流し直すまで、その分の範囲は古い読み方のままになる
- 1% と 20 件に届かない形の変化(一部の CVE だけの変化)は止まらず、印が増えていく。標準エラーの ID と理由で気づく

## 再検討する条件

- 印のある CVE が増え続け、照合の要確認が多すぎるとき
- 形の変化を、止まらないまま見逃した例が見つかったとき
